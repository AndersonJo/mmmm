Tensor 101

shape · dtype · device · view · broadcasting

Tensor = N차원 배열 + GPU + 자동미분

텐서: 차원의 사다리

비유: 0D(점) → 1D(선) → 2D(평면) → 3D(상자) → 4D(상자의 묶음)

  • 0D 스칼라: tensor(3.14) · shape=()
  • 1D 벡터: tensor([1,2,3]) · shape=(3,)
  • 2D 행렬: shape=(R,C) — Linear layer 입력
  • 3D shape=(B,T,D) — RNN/Transformer
  • 4D shape=(B,C,H,W) — CNN 이미지 배치
💡 모델이 안 돌면 90%는 shape 문제. 항상 x.shape를 찍어보세요.

shape / dtype / device 선택기

x = torch.zeros((4, 4), dtype=torch.float32, device="cpu")

총 원소 수: 16 · 메모리: 64 B

💡 float32 → float16으로 바꾸면 메모리 절반. 정확도 약간 손해. (LLM 추론에서 흔함)

브로드캐스팅 (Broadcasting)

shape이 다른 텐서를 더할 때 NumPy/PyTorch가 자동으로 차원을 맞추는 규칙.

규칙: 끝 차원부터 비교, (같다 또는 한쪽이 1)이면 OK
  • (3,4) + (4,) → 행마다 더함 ✓
  • (3,1) + (1,4) → (3,4)로 펼침 ✓
  • (3,4) + (3,) → ✗ shape mismatch

결과 shape: (3,4)

💡 attention의 mask 연산도 모두 broadcasting 위에서 동작.

슬라이싱 / 인덱싱 놀이터

Python의 슬라이싱이 N차원으로 확장. shape 6×6 행렬에서 잘라봅시다.

x[1:4, 2:5]

결과 shape: (3, 3)

💡 슬라이스는 view(메모리 공유). 복사 아님 — 수정하면 원본 변함.

reshape · view · contiguous

  • view — 메모리 그대로 두고 shape만 재해석. contiguous 텐서에서만.
  • reshape — 가능하면 view, 불가능하면 자동으로 복사.
  • contiguous() — 메모리에 일렬로 다시 깔아둠.
x = torch.arange(12) # (12,) y = x.view(3, 4) # (3,4) 같은 메모리 z = y.t().contiguous() # transpose 후 새 메모리 w = z.view(12) # ← OK
💡 transpose/permute 후엔 contiguous() 필요. 안 하면 RuntimeError.

💡 view는 shape 변환의 0 cost 버전. 가능한 한 reshape보다 view를 사용.

메모리 레이아웃 (Row-major)

2D 행렬 (3,4)은 메모리에 한 줄로 쌓여요. 이걸 어떻게 읽을지가 stride.

stride = (4, 1) # row 한 칸 = 4 step, col 한 칸 = 1 step

transpose: stride가 (1,4)로 바뀜. 메모리 순서는 그대로 — 그래서 view 불가.

결과: ✓ view 가능

💡 GPT-3 forward의 90% 시간은 matmul에서 소비됩니다.

연산 심화 ①: 원소별 + − * /

c = a * b # 원소별 곱
  • 같은 위치 원소끼리만 연산 → GPU 모든 원소 완전 병렬
  • 결과: 새 메모리 할당. In-place: a.mul_(b)
  • Broadcasting 적용: (3,4) * (4,) → 행마다 반복

메모리: 2개 읽기 → 1개 쓰기 = memory-bound. Compute 아닌 bandwidth가 병목.

💡 In-place(*=) → autograd 그래프 파괴 주의!

연산 심화 ②: 행렬 곱 @ (matmul)

x = torch.randn(3, 4) # (M=3, K=4) W = torch.randn(4, 3) # (K=4, N=3) y = x @ W # (M=3, N=3) # y[i,j] = sum(x[i,:] * W[:,j])
  • y[i,j] = x의 i행 · W의 j열 내적
  • 연산 수: M×N×K 곱셈+덧셈 (O(n³))
  • 내부: cuBLAS GEMM — 타일링으로 L1 캐시 최대 활용
  • GPT-3 forward의 90%가 여기서 소비

연산 심화 ③: sum / mean / max (축소)

x = torch.arange(12).view(3,4).float() # (3,4) x.sum(dim=0) # → (4,) 행들 합산 x.sum(dim=1) # → (3,) 열들 합산 x.sum(dim=1, keepdim=True)# → (3,1) shape 유지
  • dim=0: 행 차원이 사라짐 → 결과 (4,)
  • keepdim=True: shape 유지, broadcasting 편리
  • 메모리: 축 제거된 새 텐서. CUDA parallel reduction kernel 사용

결과 shape: (4,)

연산 심화 ④: cat / stack

a = torch.zeros(2, 3) b = torch.zeros(2, 3) torch.cat([a,b], dim=0) # (4,3) 행 이어붙임 torch.cat([a,b], dim=1) # (2,6) 열 이어붙임 torch.stack([a,b], dim=0) # (2,2,3) 새 축 추가!
  • cat: 기존 축에 이어붙임 → 차원 수 동일
  • stack: 새 차원 추가. 입력 shape 모두 동일 필수
  • 메모리: 새 할당 + 데이터 복사 — 공유 없음

연산 심화 ⑤: squeeze / unsqueeze

x = torch.randn(3, 4) x.unsqueeze(0) # → (1, 3, 4) x.unsqueeze(1) # → (3, 1, 4) x.unsqueeze(-1) # → (3, 4, 1) y = torch.randn(1, 3, 1) y.squeeze() # → (3,) 크기 1 축 제거
  • 메모리 복사 없음 — shape/stride 메타데이터만 변경 (0 cost!)
  • x[None] = x.unsqueeze(0) — batch 차원 빠르게 추가
  • 크기 1이 아닌 축에 squeeze → 무시됨

연산 심화 ⑥: permute / transpose

x = torch.randn(2, 3, 4) # stride=(12,4,1) y = x.permute(0, 2, 1) # (2,4,3) stride=(12,1,4) z = x.transpose(1, 2) # (2,4,3) 동일 y.is_contiguous() # False → view() 불가! y.contiguous() # 새 메모리에 복사 후 연속
  • 데이터 이동 없이 stride 배열만 재배치 → 0 cost
  • Non-contiguous: view() 실패, reshape()은 자동 복사
  • Attention: (B,H,T,D)→(B,T,H,D) 변환에 필수
💡 같은 색 = 같은 메모리 주소의 데이터. stride만 달라져 읽는 순서가 바뀜.

연산 심화 ⑦: argmax / topk

logits = torch.tensor([0.1, 2.3, 0.5, 1.8, 0.9, 1.2]) logits.argmax() # → tensor(1) (인덱스) logits.max() # → tensor(2.3) (값) vals, idxs = logits.topk(3) # vals=[2.3,1.8,1.2], idxs=[1,3,5] # 2D: dim 지정 x.argmax(dim=-1) # 각 행의 최대 인덱스 → (B,)
  • argmax: dtype=int64 인덱스 텐서 반환
  • topk: (values, indices) 튜플 반환, 정렬됨
  • 메모리: 입력보다 훨씬 작은 출력 → massive reduction

연산 심화 ⑧: torch.where

mask = torch.tensor([[True,False,True], [False,True,False]]) a = torch.tensor([[1,2,3],[4,5,6]]) b = torch.tensor([[10,20,30],[40,50,60]]) out = torch.where(mask, a, b) # → [[1,20,3],[40,5,60]]
  • 원소별 조건부 선택: mask ? a : b
  • Causal attention: torch.where(mask, scores, -inf)
  • 메모리: 새 텐서 할당. mask/a/b 모두 broadcast 가능
  • 내부: GPU에서 predicate + select를 단일 kernel에 수행
💡 padding mask, causal mask 적용에 필수 패턴

dtype 함정 모음

int + float

torch.tensor([1,2]) + torch.tensor([1.0, 2.0]) # → float (자동 승격)

손실 계산 시 int64 라벨 + float32 logit 자주 만남.

float16 underflow

x = torch.tensor(0.0001, dtype=torch.float16) x*x # = 0.0 (언더플로!)

대형 모델은 보통 bfloat16 사용 (지수부 더 큼).

device 섞이면

a = torch.tensor([1.], device='cuda') b = torch.tensor([2.]) a + b # RuntimeError!

언제나 같은 device에 모은 뒤 연산.

tip: x.to(device, dtype=torch.float32)로 한 번에 변환

NumPy ↔ Tensor 변환

arr = np.array([1.0, 2.0, 3.0]) t = torch.from_numpy(arr) # 메모리 공유! arr2 = t.numpy() # 메모리 공유!
  • from_numpy — 같은 메모리 공유. 빠름.
  • tensor(arr) — 항상 복사. 안전.
  • GPU 텐서 → numpy: t.cpu().numpy() 거쳐야 함
  • requires_grad=True 텐서는 .detach() 후 numpy
💡 plot할 땐 항상 x.detach().cpu().numpy() 패턴.

GPU 가속의 마법

CPU → GPU로 옮기기만 해도 10~100배 빨라지는 이유: 동시에 수천 개 코어.

x = torch.randn(4096, 4096) %timeit x @ x # CPU: ~1.5s x = x.to('cuda') %timeit x @ x # GPU: ~0.02s (75배)

예상 CPU 시간: 0.012 s · 예상 GPU 시간: 0.0002 s

💡 작은 크기에선 PCIe 전송 비용이 더 커서 오히려 GPU가 느릴 수도.

흔한 실수 5선

1. shape 미스매치

Linear(10, 5)에 (4, 8) 넣으면 폭발. 항상 print(x.shape).

2. requires_grad=False 깜빡

모델 파라미터인데 학습 안 되면 이걸 의심.

3. .item()으로 GPU 동기화

학습 루프 안에서 .item()은 GPU를 강제로 멈춰요.

4. inplace 연산이 autograd 깨먹음

x.add_(1)은 in-place. requires_grad 텐서엔 위험.

5. detach 안 하고 numpy 변환

RuntimeError: Can't call numpy() on Tensor that requires grad.

정리

shape

차원의 길이 튜플. 디버깅 1순위.

dtype

float32 기본, fp16/bf16은 메모리·속도, int64는 라벨.

device

cpu/cuda/mps. 같은 device끼리만 연산.

broadcasting

끝 차원부터 맞춤. attention mask 핵심.

view vs reshape

view는 0 cost, contiguous 필요.

NumPy ↔ Tensor

from_numpy 메모리 공유, .cpu().numpy()는 안전.
