Autograd & 계산 그래프

PyTorch가 손으로 ∂L/∂W 를 계산해 주는 마법

왜 자동 미분이 혁명인가

비유: 가계부. 매 forward마다 "누가 누구에 곱해졌는지" 영수증처럼 기록 → backward 시 거꾸로 훑어 chain rule 자동 적용.
  • 손 유도 → 실수투성이
  • 수치 미분 → 느리고 부정확
  • 자동 미분 → 정확 + 빠름
💡 Theano(2007)가 처음 대중화. 이후 모든 프레임워크의 기반.

requires_grad: 추적 스위치

x = torch.tensor(3.0, requires_grad=True) y = x**2 + 2*x + 1 y.backward() x.grad # = 2x + 2 = 8
  • requires_grad=True 텐서로 만든 결과는 자동 추적
  • nn.Parameter는 기본 True
  • 입력 데이터는 보통 False

y=x²+2x+1 = 16.0 · dy/dx=2x+2 = 8.0

💡 추적 켜지면 메모리·연산 늘어남. 추론 시엔 끔.

드래그-투-빌드 계산 그래프

a = x * w b = a + bias L = b ** 2

💡 dL/dw = 2b · x — 입력이 클수록 weight grad도 큼. (BERT 학습률 1e-4 이유)

연쇄 법칙을 단계별로

  1. ∂L/∂L = 1 (시작점)
  2. L = b² → ∂L/∂b = 2b
  3. b = a + bias → ∂b/∂a = 1, ∂b/∂bias = 1
  4. ∂L/∂a = ∂L/∂b · 1 = 2b
  5. a = x·w → ∂a/∂w = x, ∂a/∂x = w
  6. ∂L/∂w = 2b · x ✓
  7. ∂L/∂x = 2b · w ✓
  8. ∂L/∂bias = 2b ✓
💡 모든 단계가 "지역 미분 × 흘러온 grad". GPU 병렬화에 최적.

leaf vs non-leaf 텐서

  • Leaf: 사용자가 만든 텐서 (입력, 파라미터). .grad 보존.
  • Non-leaf: 다른 텐서로 계산된 중간값. .grad = None (기본).
  • 중간 grad 필요하면 x.retain_grad()
x = torch.tensor(2.0, requires_grad=True) # leaf y = x * 3 # non-leaf z = y ** 2; z.backward() print(x.grad) # 12.0 ✓ print(y.grad) # None (기본) y.retain_grad() # 다음 backward부턴 보존

💡 메모리 절약 설계 — 대부분 중간값은 backward 후 폐기.

grad 누적 함정

backward 호출마다 .grad를 += 누적. 매 step zero_grad 필수.

for x, y in loader: optimizer.zero_grad() # ← 잊지 말기 loss = loss_fn(model(x), y) loss.backward() optimizer.step()

x.grad = 9

💡 누적 디자인은 일부러 — gradient accumulation으로 큰 배치 흉내 가능.

retain_graph: 두 번 backward

기본적으로 backward()는 그래프를 지움(메모리 절약). 같은 그래프를 두 번 쓰려면:

loss1.backward(retain_graph=True) loss2.backward() # 같은 그래프 재사용
  • GAN, multi-task 등에서 필요
  • 안 쓰면 RuntimeError: backward through the graph a second time
💡 99% 케이스는 loss = loss1 + loss2로 합쳐서 한 번 backward — retain_graph 안 써도 됨.

no_grad / detach: 추적 끄기

추론·평가 시 grad 불필요. 추적 끄면 메모리 30~50% 절감.

with torch.no_grad(): pred = model(x) # 그래프 안 만듦 y = (x * 2).detach() # 이 노드부터 grad 끊김
  • no_grad — context 안 모든 연산
  • detach() — 특정 텐서만 분리
  • eval() — Dropout/BN 모드 변경 (no_grad와 다름!)

💡 추론 시 둘 다 써야: model.eval(); with torch.no_grad():

실전 디버깅: grad가 None일 때

증상원인해결

autograd 그래프 직접 보기

모든 텐서에 .grad_fn이 붙음. 어떤 연산으로 만들어졌는지 추적 가능.

x = torch.tensor(2.0, requires_grad=True) y = x ** 2 print(y.grad_fn) # PowBackward0 print(y.grad_fn.next_functions) # ((AccumulateGrad, 0), )
  • PowBackward0 — pow 연산의 backward 함수
  • AccumulateGrad — leaf의 .grad에 += 하는 노드
  • 이게 모여 거대한 DAG
💡 디버깅 도구: torchviz.make_dot(loss).render()

Higher-order grad (2차 미분)

x = torch.tensor(2.0, requires_grad=True) y = x**3 g1 = torch.autograd.grad(y, x, create_graph=True)[0] # 3x² = 12 g2 = torch.autograd.grad(g1, x)[0] # 6x = 12
  • 2차 미분 = Hessian — 메타러닝, MAML, 적대적 공격
  • 비용 ~2배. 강력함

💡 고차 미분 덕에 differentiable physics, neural ODE 분야 가능.

정리: Autograd 6가지

1. requires_grad

추적 스위치.

2. backward()

거꾸로 훑어 grad 채움.

3. zero_grad

매 step 호출.

4. detach/no_grad

추론 시 메모리 절약.

5. retain_grad/graph

중간값/그래프 유지.

6. higher-order

create_graph=True로 2차.
