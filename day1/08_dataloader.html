Dataset & DataLoader

데이터를 모델까지 흘려보내는 파이프라인

← → 방향키로 이동 · 슬라이더와 토글로 batching/shuffle/num_workers를 직접 체험

왜 데이터 파이프라인이 중요한가

비유: 식당의 "주방 → 홀" 동선.

요리(GPU)가 빨라도 서빙(데이터 로딩)이 느리면 손님(model)은 굶는다. 흔히 "GPU starvation"이라 부름.

  • 🎯 GPU 가 데이터를 기다리고 있다면 → 파이프라인 병목
  • ⚡ num_workers, pin_memory, prefetch만 잘 잡아도 2~5× 가속
  • 📊 ResNet-50 / ImageNet에서 잘못된 파이프라인이면 GPU util < 30%

오늘 다룰 것:

  • Dataset 인터페이스 (__len__, __getitem__)
  • DataLoader: batch · shuffle · num_workers · pin_memory
  • Sampler · collate_fn · transform
  • 병목 진단과 실용 패턴

Dataset — 두 메소드만 구현

from torch.utils.data import Dataset

class MyDataset(Dataset):
    def __init__(self, data, labels):
        self.data, self.labels = data, labels
    def __len__(self):
        return len(self.data)
    def __getitem__(self, idx):
        x = self.data[idx]
        y = self.labels[idx]
        return x, y
  • __len__: 전체 샘플 수 — Sampler가 활용
  • __getitem__: 한 샘플 반환. 디스크 read · transform · normalize는 모두 여기서
  • 여러 worker가 호출 → side effect 없는 순수 함수처럼 작성
📚 "한 권의 책에서 idx 번째 페이지를 가져다 줘" 같은 인터페이스. 책장 정리(__init__) + 펼치기(__getitem__).

💡 ImageFolder, TensorDataset, MNIST 등 모든 내장 dataset도 이 두 메소드를 구현한 클래스.

두 종류 — Map-style vs Iterable-style

Map-style (대부분)

  • __len__ + __getitem__ 구현
  • 인덱스로 임의 접근 → shuffle / random_split 가능
  • 전체 메모리에 올릴 수 있는 사이즈
  • 예시 MNIST, CIFAR-10, CSV
class MapDS(Dataset):
    def __getitem__(self, i): ...
    def __len__(self): ...

Iterable-style (대용량 스트림)

  • __iter__만 구현
  • 로그 스트리밍, 매우 큰 코퍼스, S3/HTTP 원격
  • shuffle 직접 구현, worker 분배 신경
  • 예시 HuggingFace streaming=True, WebDataset
class StreamDS(IterableDataset):
    def __iter__(self):
        info = get_worker_info()
        for line in shard(info):
            yield tokenize(line)

💡 GPT-3 학습은 Iterable-style. 토큰 수 3000억 → 디스크에 다 못 올림.

DataLoader — 모든 옵션 한눈에

loader = DataLoader(
  dataset,
  batch_size=64,
  shuffle=True,
  num_workers=4,
  pin_memory=True,
  drop_last=False,
  persistent_workers=True,
  prefetch_factor=2,

  sampler=None,
)

주의: shuffle과 sampler는 양립 불가. 커스텀 sampler 쓰면 shuffle=False로.

Batch size — 왜 미니배치인가

이론: 그래디언트 추정 분산은 1/√B에 비례.

σ(grad) ∝ 1/√B batch=1 → σ ≈ 1.00 batch=64 → σ ≈ 0.125 batch=256 → σ ≈ 0.0625
  • B=1 (SGD): 매우 noisy, escape from saddle 좋음
  • B↑: 안정적, GPU 활용↑
  • B → ∞: full-batch GD (현실적이지 않음)

💡 GPT-3 학습 batch는 320만 토큰. ResNet-50 ImageNet은 256. Linear scaling rule: batch ×2 → lr ×2.

Shuffle — 왜, 어떻게

왜 필요한가?

  • 같은 순서면 매 epoch 같은 미니배치 → SGD 수렴 노이즈 패턴 고정
  • 클래스 라벨이 정렬되어 있으면 한 epoch 첫 절반 = class 0, 후반 = class 1 → 학습 망함
  • train: 반드시 shuffle=True
  • val/test: shuffle=False (재현성)

💡 컬러로 클래스 표시. shuffle OFF면 한 batch에 같은 클래스만 모임 → loss 그래디언트 한쪽으로 치우침.

num_workers — 병렬 데이터 로딩

worker가 많으면 데이터 준비를 GPU 학습과 겹치게 할 수 있어요.

총 시간 = 8.0s (가상)

  • 0 = 메인 프로세스 (디버깅/작은 데이터)
  • 너무 많음 → RAM 폭발, fork 오버헤드
  • Mac/Windows: if __name__ == '__main__': 가드 필수
  • Jupyter는 0 권장 (일부 환경)

💡 경험칙: CPU 코어 수의 절반에서 시작 (예: 16-core → workers=8).

collate_fn — 가변 길이 시퀀스 처리

문제: NLP에서 문장 길이가 모두 다른데 텐서로 만들려면 같은 모양이어야. 기본 collate(stack)는 실패.

def collate(batch):
    seqs, labels = zip(*batch)
    seqs = [torch.tensor(s) for s in seqs]
    pad = nn.utils.rnn.pad_sequence(
        seqs, batch_first=True,
        padding_value=0)
    lens = torch.tensor([len(s) for s in seqs])
    return pad, lens, torch.tensor(labels)

loader = DataLoader(ds, batch_size=32,
    collate_fn=collate)

💡 모듈 14 Seq2Seq에서 이 패턴을 그대로 사용. PAD 토큰은 보통 0번 인덱스.

WeightedRandomSampler 체험

클래스가 [800, 150, 50]이면 그대로 학습 → 모델이 다수 클래스만 예측.

w_i = 1 / count[label_i] sampler = WeightedRandomSampler( weights=w, num_samples=N, replacement=True)

실제 sample 분포: A:80% B:15% C:5%

💡 신용카드 사기 데이터는 fraud 비율 0.17%. 보정 안 하면 "전부 정상"이 99.83% accuracy를 만듦 — 의미 없음.

Train / Val / Test 분할

random_split

from torch.utils.data import random_split
n = len(ds)
n_tr = int(0.8 * n)
n_va = (n - n_tr) // 2
n_te = n - n_tr - n_va
gen = torch.Generator().manual_seed(42)
tr, va, te = random_split(
    ds, [n_tr, n_va, n_te], generator=gen)

💡 generator seed 고정해야 매번 같은 분할.

주의 사항

  • 시계열은 random split 금지 → 반드시 시간 순서
  • 그룹 leakage: 같은 환자/유저가 train·test 양쪽에 → 평가 부풀림. GroupKFold
  • val로 hyperparameter 튜닝, test는 마지막 한 번만
  • 흔한 비율: 80/10/10, 70/15/15, 또는 K-fold
  • stratified split: 클래스 비율 보존 (sklearn)
💡 ImageNet은 train 1.28M / val 50k / test 100k. test는 라벨 비공개라 val로 보고.

Transform — 전처리와 증강

이미지 (torchvision)

from torchvision import transforms as T

train_tf = T.Compose([
    T.RandomResizedCrop(224),
    T.RandomHorizontalFlip(),
    T.ColorJitter(0.2,0.2,0.2),
    T.ToTensor(),
    T.Normalize([0.485,0.456,0.406],
                [0.229,0.224,0.225]),
])
val_tf = T.Compose([
    T.Resize(256), T.CenterCrop(224),
    T.ToTensor(), T.Normalize(...),
])

증강은 train에만!

  • val/test에 augment 적용하면 평가가 흔들림
  • augment는 __getitem__ 내부에서 호출 → 매 epoch 다른 이미지
  • num_workers > 0이면 CPU에서 병렬
  • NLP의 토크나이즈도 transform의 일종
데이터가 부족할 때 augment는 "공짜 데이터" 효과. 회전된 7도 7임을 모델에게 가르치는 일.

💡 ImageNet 정규화 평균 [0.485, 0.456, 0.406]은 1.28M 이미지의 RGB 평균. 새 데이터셋은 직접 계산 권장.

커스텀 Compose

class Compose:
    def __init__(self, ops):
        self.ops = ops
    def __call__(self, x):
        for op in self.ops:
            x = op(x)
        return x

Q&A — 자주 묻는 질문

Q1. shuffle=True인데 sampler 지정해도 되나요?

아닙니다. RuntimeError. sampler는 인덱스 추출 전략 = shuffle을 포함. 하나만 쓰세요.

Q2. pin_memory=True는 항상 켜야 하나요?

CUDA 사용 시만 의미가 있어요. CPU만 쓰면 무의미하고 RAM 낭비.

Q3. epoch 끝마다 RAM이 늘어나는데?

__getitem__ 안의 캐시/append가 의심. persistent_workers=False로 워커가 매 epoch 재시작되게 → 확실한 누수 진단.

Q4. 마지막 batch가 작으면 BN/loss가 흔들립니다.

drop_last=True로 버리거나, batch_size로 정확히 나누어떨어지게 데이터를 자르세요.
